# mtevil v0.3.1 (Masking & Cover Reliability)

Релиз улучшает устойчивость и достоверность FakeTLS-маскировки (HTTPS-cover) без изменения формата клиентских ссылок `t.me/proxy` и без ломки существующих `config.json`.

## Что нового

- **Автоматический пропуск недоступного IPv6 и failover для `cover` (`M1`):** `CoverResolver` проверяет наличие маршрута IPv6 без отправки пакетов и пропускает не-loopback AAAA-адреса при отсутствии IPv6, а при отказе первого адреса перебирает остальные кандидаты в рамках бюджета `handshake_timeout_secs` с сохранением last-known-good (LKG) кэша.
- **Свежий X25519 `key_share` на каждое соединение (`M3`):** вместо статического пула из 64 ключей сервер генерирует свежую пару X25519 (`RFC 7748`, `subtle::ConstantTimeEq`, без `unsafe`) на каждый FakeTLS `ServerHello`.
- **Автокалибровка размера `ServerHello` flight по `cover` (`N1`):** при старте и далее раз в сутки (`86 400 с`) в фоне выполняется один ограниченный TLS 1.3 handshake с `cover` для `sni`. Измеренный размер `AppData` flight (в пределах `512..=10240` байт) используется как `fake_tls_cert_bytes`, **если пользователь не задал `fake_tls_cert_bytes` вручную** в `config.json` (или флагом `--fake-tls-cert-bytes`). При недоступности `cover` сохраняется предыдущее значение (LKG) и пишется событие `cover_calibration_failed` в телеметрию; data-path и accept-loop не блокируются.
- **Обновлённые дефолты и мастер (`M2`, `N1`, `N2`):**
  - `DEFAULT_CERT_JITTER` снижен со `128` до `±16` байт.
  - Новый дефолтный SNI мастера — `mozilla.org` (обоснование по реальным замерам ниже); для новых установок `deploy/setup.py` не фиксирует `fake_tls_cert_bytes` в `config.json`, позволяя автокалибровке подстраиваться под `cover`.
  - Мастер `mtevilctl setup` проверяет достижимость выбранного `cover` с текущего VPS и предупреждает, если домен не отвечает.

## Что меняется при обновлении существующих установок

1. **`config.json` и `sni` не перезаписываются:** если в вашем `config.json` уже указаны `sni`, `cover` или `fake_tls_cert_bytes` (например, `2878`), они сохраняются без изменений; автокалибровка **не** переопределяет явно заданный `fake_tls_cert_bytes`.
2. **Если `fake_tls_cert_bytes` не задан в `config.json`:** `mtevil` автоматически откалибрует размер записи под реальный ответ `cover` при запуске и будет обновлять его раз в 24 часа.
3. **Если `fake_tls_cert_jitter` не задан в `config.json`:** новое значение по умолчанию — `±16` байт (в старых конфигах, где явно записано `256` или `128`, остаётся значение из файла).
4. **Исправление IPv6/failover для `cover`:** начинает работать сразу после обновления контейнера, без ручных правок конфигурации.

## Как задать `fake_tls_cert_bytes` вручную

Чтобы отключить автокалибровку и зафиксировать конкретный размер fake-записи сертификата (от `512` до `10240` байт), добавьте или обновите параметр в `config.json` (в каталоге установки, например `/opt/mtevil/config.json`) и перезапустите сервис:

```json
{
  "fake_tls_cert_bytes": 4320,
  "fake_tls_cert_jitter": 16
}
```

После правки перезапустите контейнер:

```bash
mtevilctl restart
```

Для возврата к автоматической калибровке удалите ключ `"fake_tls_cert_bytes"` из `config.json` и выполните `mtevilctl restart`.

### Почему `mozilla.org`, и где профиль ещё не совпадает до `M4`

- **`mozilla.org` ближе всех к текущему wire-профилю `mtevil`:** совпадают число TLS-записей (`3`), порядок расширений `ServerHello` (`[51, 43]`, `JA3S = eb1d94daa7e0344597e756a1fb6e7054`), отсутствие `NewSessionTicket` (`0`) и глобальная доступность с зарубежных VPS (в отличие от `ya.ru`/`vk.com`, ориентированных на РФ). При автокалибровке (`4320` Б) суммарный размер первого flight (`4458` Б) совпадает с `mozilla.org` байт-в-байт.
- **Где профиль пока отличается (до `M4`, см. [ADR-003](../adr/003-masking-improvements.md)):**
  1. Для доменов `wikipedia.org`, `kernel.org` и `vk.com` реальный сервер отправляет **6 TLS-записей** (4 отдельных `0x17` для `EncryptedExtensions`, `Certificate`, `CertificateVerify`, `Finished`), порядок расширений **`[43, 51]`** и **2 `NewSessionTicket`** после клиентского `Finished` — `mtevil` до `M4` всегда отдаёт 3 записи, `[51, 43]` и 0 тикетов.
  2. `mtevil` выбирает первый шифр `0x1301..0x1303` из списка клиента (в отличие от серверов вроде `kernel.org`, которые предпочитают `0x1302`).
  3. Пересылка реального `ServerHello` `cover` (или согласование `M4` для многозаписных профилей) остаётся отдельной будущей задачей.
