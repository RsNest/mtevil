# mtevil v0.2.0

Стабильный релиз `mtevil` с усиленной отказоустойчивостью, защитой канала `edge → egress` и изоляцией секретов. Существующие клиентские ссылки `t.me/proxy`, `config.json` и пользователи сохраняют совместимость.

## Что улучшилось для пользователей

- **Быстрый failover `edge → egress`:** hedged-подключения, per-node адаптивные таймауты и circuit breaker для `ordered` и `round-robin` сокращают переключение при отказе основного `egress` с ~2 с до ~0.35–0.5 с (`0` ошибок в Linux A/B-прогонах `v0.1.5` vs `v0.2.0-rc.1`), а восстановление после недоступности всех `egress` — с ~13 с до ~0.1 с.
- **Устойчивость процесса:** accept-цикл переживает всплески `EMFILE`/`ECONNABORTED` без падения listener'а; автоматический расчёт бюджета файловых дескрипторов и `ulimits.nofile`; фоновое кэширование DNS для `cover` без блокировки трафика.
- **Безопасность `edge → egress` (`MTV3`):** аутентификация префейса по `HMAC-SHA256` с защитой от replay и окна времени `±30 с`, фильтрация источников по CIDR (`egress_allow_from`) и защита от перебора на IP без ложных блокировок от отменённых hedge-попыток.
- **Изоляция секретов и данных:** том `state` (`proxy-secret`, `users.json`, `egress-token`, `allowed-sni.txt`) монтируется только для чтения (`:ro`), а `replay.bin`, статистика и алерты вынесены в отдельный том `replay`. Горячая перезагрузка `users.json` и длинные однонаправленные загрузки дольше `idle_timeout_secs` работают без обрывов.
- **Снижение нагрузки и наблюдаемость:** число системных вызовов `getsockopt(TCP_INFO)` снижено на 92–99.9% по данным `strace` на Linux, добавлен опциональный localhost-only эндпоинт Prometheus `/metrics` и ограниченная очередь webhook-алертов.

## Обновление, проверка и откат

При обновлении с `v0.1.5` команда `mtevilctl update` автоматически и точечно мигрирует `compose.yaml` и `config.json` на схему `state:ro` + отдельный том `replay` + сервис `init`, сохраняя пользовательские правки `compose.yaml` и исходные резервные копии `compose.yaml.pre-v0.2` и `config.json.pre-v0.2` (не перезаписываются при повторе).

При обновлении контейнер перезапускается с graceful drain (`drain_timeout_secs`, по умолчанию `5 с`): активные сессии кратковременно прерываются, после чего клиент Telegram автоматически переподключается по той же ссылке.

- **Обновление (канал `stable` по умолчанию):**
  ```bash
  mtevilctl update
  ```
- **Проверка статуса и версии:**
  ```bash
  mtevilctl status
  ```
- **Откат на предыдущую версию (`v0.1.5`):**
  ```bash
  mtevilctl rollback
  ```

## Порядок обновления для разделённой схемы (`edge → egress`)

> **Важно:** `edge v0.2.0` по умолчанию использует протокол `MTV3`, который `egress v0.1.5` не поддерживает. В обратную сторону совместимость сохранена (`egress v0.2.0` по умолчанию принимает `MTV2` через `egress_accept_legacy: true`).

1. **Сначала обновите все серверы `egress`:** выполните `mtevilctl update` на каждом `egress`. Существующие `edge v0.1.5` продолжат работать без потери совместимости.
2. **Затем обновите серверы `edge`:** выполните `mtevilctl update` на каждом `edge` — они автоматически перейдут на `MTV3`. При сбое сквозной проверки Telegram `mtevilctl update` автоматически откатит предыдущую версию.
3. *(Опционально)* После обновления всех `edge` можно отключить приём `MTV2`, добавив `"egress_accept_legacy": false` в `config.json` на `egress` и перезапустив контейнер.

## Известные ограничения

- **`edge` — единая точка отказа (SPOF):** failover защищает от падения узлов `egress` и проблем между `edge` и `egress`, но не от недоступности самого `edge`-сервера.
- **Кратковременное прерывание сессий при обновлении:** `mtevilctl update` перезапускает контейнер; текущие TCP-соединения закрываются, затем Telegram переподключается автоматически.
- **Область поддержки:** Linux `x86_64` и IPv4 (`direct` и `edge → egress`). Сквозной IPv6 не проверялся и не заявляется.
- **Без ME-пула и `ad_tag`:** поддерживаются только режимы `direct` и `edge → egress`, без middle-end пула и рекламного `ad_tag`.
