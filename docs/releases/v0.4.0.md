# mtevil v0.4.0

### Что нового
- **Нативный `WSS`-транспорт для каскада `edge → egress` без внешних SSH/VPN-туннелей ([ADR-005](../adr/005-wss-egress-and-turnkey-443.md)):**
  - Параметр `egress_upstreams` на `edge` теперь принимает защищённые адреса `wss://host[:port]/<secret-path>[?connect=IP:PORT]` (наряду с классическими `IP:PORT` и `tcp://IP:PORT`).
  - На `egress` добавлен опциональный секретный путь `egress_ws_path` (`mtevilctl setup --egress-ws`), позволяющий принимать соединения от `edge` за обычным `Caddy` или `nginx` на порту `:443` с двухконтурной защитой (точная проверка пути + криптографическая аутентификация `MTV3`/`MTV4` с защитой от повторов и учётом `X-Real-IP` / `X-Forwarded-For` за loopback-прокси).
  - **Тёплый пул независимых соединений (`WsWarmPool`, `egress_ws_pool_size = 4`):** каждая клиентская сессия получает собственный заранее прогретый `TLS + WebSocket` сокет без общего TCP-бутылочного горлышка — исключён межпользовательский Head-of-Line blocking (характерный для `ssh -L`) и лишний RTT на рукопожатие.
- **Управление выходами одной командой (`mtevilctl egress`):**
  - Добавлены команды `mtevilctl egress list`, `add <адрес>`, `del <адрес|номер>`, `strategy <ordered|round-robin>`, `hedge <мс>` и `check` с автоматической проверкой `check-egress`, маскированием секретных путей `wss://.../***` и откатом при сбое.
- **Режим совместного порта `:443` (`mtevilctl setup --shared-443`) и гигиена доменов:**
  - Новый режим `--shared-443` (пункт **5** в мастере) настраивает `mtevil` на `127.0.0.1` с `proxy_protocol: true` и внешним портом ссылок `:443` (`MTEVIL_PUBLIC_PORT=443`), формируя готовые шаблоны для `nginx stream (ssl_preread on)` и `Xray fallbacks (xver: 2)`, чтобы не уводить зарубежные узлы на уязвимые высокие порты.
  - Встроенный линтер гигиены доменов и `SNI` предупреждает при наличии стоп-слов (`mtevil`, `vpn`, `proxy`, `xray` и др.) в имени поддомена.
- **Автономный `webproxy` (`--managed-caddy`), профиль `--cdn` и `mtevilctl tuning` (`[experimental]`):**
  - Экспериментальный флаг `--managed-caddy` поднимает контейнер `caddy` с автовыпуском сертификата Let's Encrypt в составе `compose.yaml`; экспериментальный флаг `--cdn` генерирует конфигурацию для работы одиночного зарубежного узла за Cloudflare (в офлайн-CI живая работа ACME и Cloudflare не проверяется).
  - Экспериментальная команда `mtevilctl tuning` позволяет управлять `client_mss` и `client_mss_bulk` с явным предупреждением об асимметрии TCP `MSS` (RFC 9293) до подтверждения полевыми замерами.
